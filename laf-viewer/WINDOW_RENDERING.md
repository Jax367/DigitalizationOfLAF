# 展开闪动的原因与方案

当前桌面小窗使用 Electron 的 transparent:true、frame:false。详情仍在主窗内部，展开与收起调用 main.cjs 的 window:detail，通过 setBounds 改变原生窗口的宽度；左侧展开还改变原生窗口的 x 坐标。网页布局、浏览器绘制和 Windows 桌面合成是不同阶段，网页的双 requestAnimationFrame 并不能保证系统已提交同一帧。此前已修复的标题字号和布局宽度跳变，不等于修复透明表面的重绘闪动。

最主要的嫌疑是透明原生窗口调整尺寸与合成时序，具体 GPU、驱动或窗口层级是否进一步放大问题尚未通过系统画面录制/追踪确认。设备网络请求不改变窗口尺寸，不能用请求变慢解释整个主窗闪动。为 Windows+D 调整层级仍是额外因素；目前层级只在前台状态变化时更新，不再持续置序。

Electron 官方说明透明窗口有缩放限制；官方窗口缩放文章也描述了浏览器 viewport 更新、裁剪与重绘先后导致画面异常的机制。不能把这些说明当作当前版本必然存在同一缺陷的证明。

## 可行方案

| 方案 | 实现方式 | 取舍 |
|---|---|---|
| 推荐：详情拆成侧边独立窗口 | 主窗展开/收起时不调用 setBounds，仅显示/隐藏可复用的详情窗。窗口创建时隐藏，内容绘制后显示；跟随主窗移动、左右对齐，只保留一个详情窗，详情宽度独立调整。关闭主窗和权限失效时同步隐藏。 | 保留透明主窗、侧边详情和宽度调整；需处理两窗之间的定位、焦点、多屏边界和桌面层级。可以消除由主窗缩放引起的闪动，详情自身仍需视觉验证。 |
| 主窗保持固定尺寸，内部覆盖详情 | 使用 CSS 在固定原生窗口内覆盖部分列表，动画只使用 opacity/transform。 | 改动较小；详情会占用或遮挡原有列表区域，无法额外向窗口外展开。 |
| 提供不透明稳定模式 | 使用非透明原生窗口，保留无边框外观和现有侧边展开。 | 对当前结构改动较小，需验证；该模式无法真正透出桌面背景。 |

仅延长渐变时间、增加延时、换字体或反复重绘不能解决主窗透明表面缩放这个触发条件。不建议直接把关闭 GPU 当作正式修复：它只能作为诊断对照，并可能增加 CPU 占用或产生其他显示问题。

0.7.4 修正双击入口并保留当前展开实现，尚未实施上述结构改造。下一步建议采用侧边独立详情窗，并用系统画面录制验证展开/收起、快速切换记录、左右侧、多屏缩放与 Windows+D。0.7.2 修改前存档仍保留在 archives/viewer-0.7.2-before-detail-experiment。

## 0.8.0 已实施

已使用独立侧窗（src/side-detail.cjs、ui/detail.*）。主窗的展开接口不再调用 setBounds，侧窗先隐藏创建、绘制后显示，关闭时隐藏复用；主窗主动最小化、关闭和设备授权失效时同步收起。宽度与图片读取只作用于侧窗，侧窗仅暴露必要的只读 IPC。实际验证覆盖主窗原生 resize 事件数为 0、展开/关闭/换记录时主窗坐标和尺寸完全不变、侧窗跟随移动、左右位置和宽度持久化、缓存图片、系统鼠标双击独立浏览、Windows+D 两窗可见。此改造移除了主窗透明表面缩放的触发条件；不同机器上的视觉表现仍应结合实际使用观察。

## 0.8.1 内容切换

详情背景与关闭按钮不再因换记录而淡出或重建；新正文和缓存图片在离屏区域准备、解码后一次提交，在透明正文层间交叉淡化 180ms，等待期间继续显示旧内容。快速切换以序号丢弃过期结果，正在显示的原生窗口不再重复 showInactive；首次打开和关闭仍使用整个面板的渐变。减少动态效果设置会跳过正文动画。验证包含面板整体 opacity 逐帧恒为 1（背景透明度仍遵循设置）、背景颜色不变、动画真实运行、固定头部节点保持不变、模拟 450ms 图片延迟及过期结果、切换期间 showInactive 调用数为 0。
